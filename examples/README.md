# 输出长什么样

`sample-vault/` 是从**真实档案**里裁出来的样例 —— 作者本机 17 份裁剪档案（由 89 个真实 DSH 会话里剪出）跑出来的完整库，不是手写排版。唯一改动是把机器名换成了 `you`。

完整 55 页（17 个会话 / 5 个项目 / 30 个主题），这里只挑了 5 页。想自己复现同样结构，用仓库自带的精简 fixture 就行（3 个会话 / 9 页）：

```
memloom build --out out/vault --root tests/fixtures
```

| 页面 | 看什么 |
|---|---|
| [`00-总索引.md`](sample-vault/00-总索引.md) | 项目列表、主题分类、最近会话 —— 打开库的第一屏 |
| [`20-会话/2026-10-29-…-obsidian-agent.md`](<sample-vault/20-会话/2026-10-29-3f395ff1-obsidian-agent.md>) | 一页会话：时间跨度 / 轮次 / 工具统计 / 关键 prompt / 错误 / 碰过的文件 |
| [`30-主题/工具-present.md`](<sample-vault/30-主题/工具-present.md>) | 一页主题：为什么这些会话被归到一起，证据是什么 |
| [`90-原文归档/README.md`](<sample-vault/90-原文归档/README.md>) | 归档不复制原文，只留一张「哪条会话在哪份档案」的表 |
| [`99-使用说明.md`](<sample-vault/99-使用说明.md>) | 库自己的说明书：读法、regen 命令、边界 |

在 Obsidian 里打开这个目录就能看到 `[[双链]]` 的样子；直接看 markdown 也能读，只是链接是纯文本。

关于内容边界：页面上每一个字都来自你的 prompt、模型的公开回复、工具输出，或者规则抽出来的结构（路径、命令、错误指纹）。**不含**模型的 `reasoning` / `thinking`，也**不含**任何 LLM 撰写的总结 —— v0.1 全程零模型调用。

其中一个「空」也是真实的：这套 17 会话的样例里 `代码` 分类下没有页。路径分量要跨 ≥3 个会话才会立主题，17 份档案里没有一个达标；作者全量跑 117 个会话时这一栏才长出来（`代码-*/` 主题若干）。看不到不是坏了，是样本不够大。
