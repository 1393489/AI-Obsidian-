# 架构与取舍

一句话：**只读档案 → 规则抽取 → 聚类 → 渲染 markdown**。四步，四层，谁都不回头改上一层。

```
adapters/          每个来源一个类，把档案读成 Session/Turn/ToolUse
   ↓
extract.py         从文本里抠东西：路径、命令、错误行、指纹
   ↓
group.py           会话 → 项目（cwd + 共享文件并查集）+ 主题（错误/路径/命令）
   ↓
render.py          项目/会话/主题/索引/说明 → markdown
   ↓
vault.py           扫盘、并行加载、只写变化、删过期生成页
```

`cli.py` 只是很薄的一层壳（`doctor` / `scan` / `build`）。

## 三个不那么显然的决定

### 1. 为什么不用 LLM

最直接的替代方案是「把每个会话丢给模型，让它总结」。放弃它的理由不是省钱：

- **不可复现。** 同样的档案跑两次得到两份不同的库，它会进 git、会被 diff，然后就全是噪音。
- **信任边界。** 你的会话里有密钥提示、内部路径、报错原文。一个本地工具没有理由把它们发到任何地方。
- **装不上。** 想用的人先得配 key、装 SDK、忍 `pip` 解析依赖 —— 一个「读文件生成 md」的工具不该有这些前置条件。

所以 v0.1 全部规则化。规则化的代价是**名字不好听**（`踩坑-Error- ECONNREFUSED`），这个代价写在 README 的局限里，而不是假装不存在。v0.2 会加 `--enrich`，把「起名字」这一步单独交给 LLM，且输出落在单独的 `.memloom/enrich.json` 里 —— 增强是补丁，不是主干。

### 2. 项目聚类：cwd 不够，必须看文件

真实数据上的第一个版本就翻车了：87 个 DSH 会话全部在同一个 workspace 目录跑，`cwd` 分组把它们塌成 1 个项目页，内容 100 KB 且完全没有导航价值。

现在的做法是三步：

1. **按规范化 cwd 分桶**（`\\` → `/`、去尾斜杠、小写比较）。
2. **并查集合并**：两个桶之间有 ≥ 2 个共享文件（同一路径出现在两边的抽取结果里）就并起来。这一步解决「人在 `repo/` 和 `repo/sub/` 之间来回跑」。
3. **过大的桶按文件重新切分**：> 12 个会话的桶，取每个会话的主要目录（第二级路径组件）当候选名，再按共享文件把会话聚成子组。子组只有 1 个会话时不发射；名字拿不到就并回父桶，而不是硬起一个 `default-workspace · review` 这种垃圾名。

项目命名有两条硬规矩：**用父目录名**（`- 【声音】` 这种后缀全是被 shlex 切开的误报），以及**通用目录名不当名字**（`src` / `app` / `lib` / `state` / `chrome-profile` 全在 `_GENERIC_DIRS` 里）。

### 3. 主题 = 可验证的结构，不是关键词

「关键词提取」在会话日志上表现很糟：满屏 `file` / `error` / `the`。所以主题只认三件能在数据里数出来的事：

| 类别 | 判据 | 为什么可信 |
|---|---|---|
| `踩坑` | 同一**错误指纹**出现在 ≥ 2 个会话里 | 指纹做了归一化（UUID / 时间戳 / 十六进制 / 路径 / 数字 → 占位符），两次撞上同一个指纹，基本就是同一个坑复发了。 |
| `代码` | 同一**二级路径组件**出现在 ≥ 3 个会话里 | 说明你反复在那块代码里干活。 |
| `工具` | 同一**非通用命令**出现在 ≥ 3 个会话里 | `pytest` / `gh` / `robocopy` 反复出现 = 这条工作流值得记一页。 |

上限也是硬的（`踩坑` 40 / `代码` 24 / `工具` 12）：主题页的价值在于**少**，多了就是第二本流水账。

## 抽取的几个反直觉点

- **只读提示、工具输出和回复正文**，不读 `reasoning` / `thinking`。思考过程里全是「如果失败了就……」这类假设句，喂给错误检测会产生大量假踩坑页（这个 bug 是真的发生过：一份 duty.md 生成了 2.2 KB 的假页面）。
- **URL 先剔掉**再找路径，否则 `https://example.com/a/b` 会被当成 posix 路径 `/a/b`。
- **被包含的子路径不算证据**：抽到 `C:/work/app/src/main.ts` 时，`C:/work/app` 那条计数要减掉 —— 否则父目录永远第一名，聚类全糊在一起。
- **错误行有格式闸门**：长度 6–200、剔除 `**`/`>` 之类 markdown 前缀、含 ≥ 2 个中文逗号或括号的句子直接判为非错误（那是散文）、空格 > 40 个的也扔掉。再加上一组具体模式（`Traceback` / `ERR_*` / `ECONNREFUSED` / `exit code: N` / `失败：` …）和一条大写的 `FAIL`。
- **Windows 路径两种分隔符都要认**。`C:/work/app.ts` 和 `C:\work\app.ts` 都得匹配 —— 前者在 shell 输出里非常常见，只认反斜杠的版本会漏掉大量证据。

## 写盘策略

- 每页第一行是 `<!-- generated by memloom -->`。**清理只删带这个标记的 `.md`** —— 你在这本库里手写的笔记永远安全。
- 内容没变就不写（逐文件比较字符串），所以第二次 `build` 的 `written` 是 0，mtime 不动，Obsidian 不会闪。
- 归档目录（默认 `90-原文归档/`）**只放一份 README 说档案在哪**，不复制原文：几十上百 MB 的 `.zstd` 复制进 vault 会让 git 和同步都难受。

## 增量解析

解析很贵（解压 + 逐事件解析），所以 `build` 会在**输出目录**里留一份缓存：`<out>/.memloom/state.json` 记每条档案的 `size`、`mtime_ns` 和适配器名；`<out>/.memloom/cache/<sha1(路径)[:16]>.json` 存这条档案解析出来的 `Session`。

- **命中条件**：`size` 与 `mtime_ns` 都没变、适配器名没变。只 stat，不读文件，所以「检查 114 个档案要不要重解析」几乎不花时间。内容变了但 size/mtime 都没变的情况理论上存在（同一秒内改同长度），实际可以忽略 —— 真要保险就 `--full`。
- **失效路径**：`state.json` 带 `version: 1`，版本不匹配就整库重解析；换了 `--adapter` 或适配器代码变了（适配器名写在条目里）也只重解析那一条；缓存文件写坏了解析失败会当作 miss。
- **写在哪**：永远在 `<out>/.memloom/`，绝不在档案目录里。档案目录对本工具只读，这是设计约束。
- **原子性**：缓存单文件先写 `.tmp` 再 `os.replace`；`state.json` 同样。中途 Ctrl-C 不会留下半个 JSON。
- **`--dry-run`**：只读缓存，不写缓存也不写 `state.json`（`Cache.read_only`），所以干跑不会污染下一次的真实构建。
- **序列化坑**：`Session.started_at` / `ended_at` / `Turn.at` 是带时区的 `datetime`，JSON 里必须 `.isoformat()`、读回来 `datetime.fromisoformat()`，否则往返一次就变成字符串，下游 `strftime` 直接炸。

## 性能

真实数据（本机 2026-11-14）：DSH 89 个 `.zstd` / 69 MB，加上 Claude Code 27 个 `.jsonl` / 220 MB，全量 19.2 s / 116 会话 / 187 页。解压是绝对瓶颈，所以 `zstd_frames` 优先找 `pyzstd` / `node`，纯 Python 兜底根本不存在（也不该存在）。

增量构建（同一个库，档案没变）：**0.8–2.0 s**，且 `written = 0`。第一次增量略慢一点（要把缓存反序列化回 `Session`），之后更快。

## 一个真实的坑：CRLF 让页面「永远在变」

prompt 和工具输出里带着 Windows 的 `\r\n`。写文件时如果用 `newline="\n"` 原样写出去，下次读回来时 Python 的 universal newline 会把 `\r\n` 折叠成 `\n`，字符串比较就永远不相等 —— 于是每次构建都重写那几页，`written` 永远不是 0。修法是写入前把 `\r\n` / 单独的 `\r` 统一成 `\n`，读写两侧用同一套换行语义。

同类的假变更还有「两个不同主题撞同一个文件名」：主题名是从错误首行截断来的，`request id` 不同但前缀相同就会撞名，后写的把先写的覆盖，于是这两页每轮都在互相覆盖。修法有两层：`fingerprint()` 把长 id 归一成 `<id>`（治本，让它们本来就是同一个主题），渲染完再对 rel 做一次唯一化，冲突的页面追加内容哈希后缀，完全相同的重复页直接丢弃。

## 不做什么

- 不做语义搜索（用 Obsidian 自己的搜索）。
- 不改、不移动、不在档案目录里写任何文件。`~/.dsh/sessions` 对本工具是只读的，这是设计约束，不是实现疏漏。
